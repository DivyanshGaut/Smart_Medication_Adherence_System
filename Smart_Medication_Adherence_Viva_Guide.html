1. Project Overview & Problem Statement

1.1 The Real-World Healthcare Problem

According to the World Health Organization (WHO), approximately 50% of patients with chronic illnesses fail to adhere to their prescribed medication routines. Non-adherence leads to severe clinical complications, preventable hospital readmissions, increased healthcare costs (over $100 Billion annually in the US alone), and preventable mortality.

Key pain points patients face include:

  • Forgetfulness & Routine Disruption: Busy lifestyles, changing schedules, and complex multiple-dose regimens.
  • Pill Burden & Inventory Mismanagement: Running out of essential medications unexpectedly without refill awareness.
  • Lack of Caregiver Visibility: Family members and doctors lack real-time visibility into whether elderly or vulnerable patients have taken their daily doses.
  • Static/Clunky Reminders: Traditional alarm apps lack intelligent scheduling, adherence rate calculations, and contextual insights.

1.2 The Elowen Solution

Elowen is a full-stack, enterprise-grade medication management and adherence analytics platform designed with patient empathy and clinical rigor. It bridges the gap between daily routines and clinical outcomes:

1.3 Key Functional Features

  1. Interactive Dose Tracking: One-click dose confirmation with live state transitions (Upcoming → Due soon → Taken / Snoozed / Missed).
  2. Automated Inventory Decrement: Recording a dose as "Taken" automatically deducts pill count from the medication table and forecasts refill dates.
  3. Clinical Adherence Algorithm: Computes statistical consistency score over a 30-day sliding window, tracking streaks and missed dose distributions.
  4. Natural Language AI Scheduler: Allows users to speak/type naturally (e.g., "Remind me to take Metformin with dinner every weekday at 7:30 PM"), parsing entity tokens into schedules.
  5. Multi-tier Care Circle: Supports consent-based permissions for primary caregivers, clinicians, and family contacts.
  6. Audit Trail & History: Complete chronological event ledger with CSV export capabilities for medical consultations.

3.1 Natural Language Processing (NLP) Scheduling Engine

One of the standout features of the platform is the rule-based Natural Language Scheduler implemented in [`ScheduleService.java`](file:///c:/Users/gdivy/Downloads/Smart%20Medication%20Adherence%20Dashboard/backend/src/main/java/com/elowen/service/ScheduleService.java).

How it works: When the patient inputs a plain English request like:
"Remind me to take Metformin with dinner every weekday at 7:30 PM"
  1. Temporal Pattern Extraction: Uses Regular Expressions (\b(\d{1,2}(?::\d{2})?\s*(?:am|pm))\b) to detect explicit times, or contextual keywords (morning → 8:00 AM, lunch → 1:00 PM, dinner/evening → 7:30 PM).
  2. Frequency Extraction: Matches keywords such as "weekday", "weekend", "every day", or "twice daily".
  3. Entity Matching: Scans the user's active medications in H2 to associate the routine with existing inventory (or creates a placeholder).
  4. Automatic Routine Generation: Synthesizes a new Schedule record and saves it directly to the database.

3.2 Adherence Rate Mathematical Formulation

The system computes the clinical adherence metric across recorded historical doses using the formula:

$$\text{Adherence Rate (\%)} = \left(\frac{N_{\text{taken}}}{N_{\text{taken}} + N_{\text{missed}} + N_{\text{skipped}}}\right) \times 100$$

Streak Calculation Logic: A continuous streak is maintained as long as no scheduled dose in the current sequence is recorded as MISSED.

6. Top 25 Viva Questions & Model Answers

Examiners frequently probe candidates on design choices, framework internals, security vulnerabilities, and database configurations. Memorize these key answers:

Q1 Why did you use Spring Boot instead of plain Java Servlets or Spring MVC?
Model Answer: Plain Servlets require manual boilerplate for request routing, parameter mapping, thread pooling, and web.xml deployment. Traditional Spring MVC requires extensive XML/Java configuration. Spring Boot provides opinionated auto-configuration, dependency starters (like spring-boot-starter-web), and an embedded Apache Tomcat server. This allowed us to package the application as a self-contained, standalone executable JAR that boots in under 3 seconds without needing a separate application server.
Q2 How does your authentication mechanism work, and why choose JWT over HTTP Sessions?
Model Answer: We implemented Stateless JWT (JSON Web Token) authentication. Traditional HTTP sessions store state in server memory (JSESSIONID), which breaks horizontal scaling when multiple server replicas are deployed behind a load balancer without sticky sessions. With JWT, all user claims (userId, email, expiration) are cryptographically signed using HMAC-SHA256 and sent in the Authorization: Bearer header. The server verifies the token signature on each request via JwtAuthenticationFilter without reading from a session store.
Q3 How are user passwords secured in the database? Why not SHA-256?
Model Answer: Passwords are encrypted using BCrypt (via Spring Security's BCryptPasswordEncoder). Plain SHA-256 is an unsalted cryptographic hash designed for fast throughput, making it vulnerable to rainbow table attacks and GPU-accelerated brute force. BCrypt automatically generates a cryptographic salt and employs a configurable work factor (default 10 iterations) making brute-force computation prohibitively expensive.
Q4 What database are you using, and does the data survive when the server is restarted?
Model Answer: We use the H2 Database Engine configured with file-based persistent storage: jdbc:h2:file:./data/adherence_db;DB_CLOSE_DELAY=-1. Unlike in-memory mode (jdbc:h2:mem:...) which deletes data when the JVM terminates, file-based H2 persists all tables, users, and logs onto the disk in the data/ folder. It also includes an embedded H2 web console accessible at /h2-console.
Q5 How does the backend communicate with the frontend during development? What is CORS?
Model Answer: The frontend (Vite) runs on port 8443 and the backend (Spring Boot) runs on port 8080. Browsers enforce the Same-Origin Policy (SOP), blocking requests between different ports unless Cross-Origin Resource Sharing (CORS) is enabled. We handled this two ways:
1. In Spring Boot, we configured a CorsConfigurationSource bean allowing incoming HTTP methods (GET, POST, PUT, DELETE, OPTIONS).
2. In vite.config.ts, we created an active proxy that routes any request matching /api directly to http://127.0.0.1:8080, eliminating CORS preflight overhead.
Q6 What happens behind the scenes when a user clicks "Take now" on a medication?
Model Answer: 1. React triggers an asynchronous fetch() request to POST /api/doses/action passing the JWT token, medication ID, and status "TAKEN". 2. Spring Boot's DoseService executes inside an ACID transaction (@Transactional): - Checks today's log: creates or updates a DoseLog entity with status Taken and current timestamp. - Retrieves the Medication entity and decrements its pillCount by 1. 3. The updated state is committed to H2. The frontend receives the response, immediately reflects the taken badge, and invokes loadOverview() to dynamically refresh the adherence KPI percentage and streak counter.
Q7 Explain the Natural Language Processing (NLP) feature. Did you use an external AI API?
Model Answer: The NLP feature is an intelligent heuristic parser implemented directly inside ScheduleService.java. It avoids latency, cost, and API downtime by parsing natural language patterns using Regular Expressions and semantic dictionary matching. It extracts: - Time entities: Explicit timestamps (e.g., "7:30 PM") or colloquial terms (dinner → 7:30 PM, lunch → 1:00 PM, morning → 8:00 AM). - Frequency entities: weekdays, weekends, daily, twice daily. - Medication entities: Matched against the user's registered medicine names. It then auto-constructs a recurring Schedule record.
Q8 What is Hibernate and what is the difference between JPA and Hibernate?
Model Answer: JPA (Java Persistence API / Jakarta Persistence) is a specification or interface standard defining how Java objects should be mapped to relational databases. Hibernate is the underlying implementation (ORM provider) that implements the JPA interfaces. In our project, Spring Data JPA acts as an abstraction layer over Hibernate, allowing us to interact with the database using repository interfaces without writing boilerplate SQL.
Q9 What design patterns are used in this project?
Model Answer:
  • Controller-Service-Repository Pattern: Strict 3-layer architecture decoupling HTTP parsing, business logic, and database queries.
  • DTO (Data Transfer Object) Pattern: Separates database entity models (User, Medication) from API payloads (UserDto, AuthRequest) to avoid exposing sensitive fields like password hashes.
  • Filter / Interceptor Pattern: JwtAuthenticationFilter extends OncePerRequestFilter to intercept every request before hitting controllers.
  • Dependency Injection & Inversion of Control (IoC): Spring manages component lifecycles using constructor-based injection.
  • Singleton Pattern: Spring Beans (Services, Repositories) are singletons managed by the Spring ApplicationContext.
Q10 How does Spring Data JPA execute queries without implementation code?
Model Answer: Spring Data JPA uses dynamic proxy generation at application startup. When we declare method signatures like findByEmail(String email) or countByUserIdAndStatus(Long userId, String status), Spring parses the method name keywords (findBy, countBy, And) and automatically generates the corresponding JPQL/SQL query at runtime.
Q11 What is the purpose of DataInitializer?
Model Answer: DataInitializer implements Spring Boot's CommandLineRunner interface. Upon initial startup, it checks if the database is empty; if so, it seeds default demo users, medications, routines, care circle members, and 30 days of dose history. This ensures that the application is immediately testable and demonstrates real adherence graphs on initial evaluation.
Q12 What is the difference between PUT and POST in your API?
Model Answer: POST is used to create new resources (e.g., POST /api/medications to add a new medicine or POST /api/auth/register to create a user). PUT is idempotent and used to update existing resources (e.g., PUT /api/user/profile or PUT /api/user/notifications to replace or update settings).
Q13 How does React manage application state in your frontend?
Model Answer: State is managed using modern React Hooks: - useState handles component-level reactive state (user profile, medication list, modal visibility, search queries). - useEffect synchronizes side-effects (fetching overview data, verifying token validity upon initial load). - useCallback memoizes data-fetching functions to prevent unnecessary component re-renders. - Persistent state (JWT token and cached user data) is stored in the browser's localStorage.
Q14 How can you scale this project for production with millions of users?
Model Answer: 1. Database Migration: Switch from H2 to a distributed, production-grade RDBMS like PostgreSQL or MySQL (simply changing application.properties datasource URL and dialect). 2. Connection Pooling: Tune HikariCP connection pool parameters. 3. Caching: Introduce Redis for frequently queried dashboard KPIs and user sessions. 4. Containerization: Dockerize the Spring Boot backend and React frontend into multi-stage Docker images orchestrated with Kubernetes. 5. Message Broker: Add RabbitMQ or Apache Kafka to handle real-time SMS/Email caregiver notifications asynchronously.

7.2 Common Examiner Traps & How to Avoid Them

  • Trap: "Is your H2 database running in memory only?"
    Defense: "No, sir/ma'am. We specifically configured jdbc:h2:file:./data/adherence_db so all transactions and logs are written to physical disk files and survive restarts."
  • Trap: "Where is your Tomcat server installed?"
    Defense: "Tomcat is an embedded dependency inside our Spring Boot JAR file (via spring-boot-starter-web). We do not require an external application server."
  • Trap: "What if someone intercepts the JWT token?"
    Defense: "In production, JWTs must always be transmitted over HTTPS (TLS encryption). Furthermore, tokens have a 24-hour expiration window and can be coupled with refresh tokens and token blacklisting for revocation."
  • Trap: "Why not use plain CSS instead of Tailwind?"
    Defense: "Tailwind CSS v4 provides utility-first CSS compiled directly into minimal, optimized stylesheet bundles, preventing CSS bloat and naming conflicts."
